# Realism plan: path-traced stills, lighting fidelity, material depth

Three independent pieces of work, each specified for one Opus subagent in its own worktree, to run after the soft-shadow, section-cut, dusk-light and 3D-measure branches have merged. They touch disjoint files and merge without conflict. Decisions taken here are final unless the implementer finds them impossible; anything left open is marked "call".

Shared rules: CLAUDE.md applies (brand tokens, `<Loader>` for every wait, listing 91770873 only, `npm run check` and `npm run build` before committing, screenshots in headless Chromium with the SwiftShader flags). World frame: x right, world z = plan y, y up. Frames are on demand: `invalidate()` after every change.

## 1. Path-traced stills ("Render")

**Why.** The orbit view is a preview; a buyer deciding on an extension wants one convincing picture of it at a chosen time. A path tracer gives true bounced light, soft sky light, glass and colour bleed from the existing scene with no new content. It runs only when asked and costs the live view nothing.

**Library.** `three-gpu-pathtracer@^0.0.27` with `three-mesh-bvh@^0.9.16` (peer deps `three>=0.185`; `xatlas-web` is a declared peer that npm will install and we never import). Lazy-load it from one module so neither the app shell nor the Viewer chunk grows: `const loadTracer = () => import("./pathtrace")`, the pattern `Effects` uses in `src/three/Viewer.tsx`. Read `node_modules/three-gpu-pathtracer/README.md` for the exact `WebGLPathTracer` API before writing code; the names below are from memory and the README wins.

**Files.**
- `src/three/pathtrace.ts` (new, lazy): `renderStill(id, pose, opts, onProgress, signal): Promise<Blob>`.
  - Gets the capture target from `getCapture(id)` (`src/three/captureRegistry.ts`): renderer, scene, camera.
  - Hides what must not be traced using the existing `exportable()` in `src/three/capture.ts` (export it): sky dome, Points halos, instanced light pools, helpers, Html, ShaderMaterial meshes. Restore visibility in `finally`.
  - Camera: clone the viewer's PerspectiveCamera, apply `pose` (position, target) exactly as `captureAt` does, set aspect from `opts.width/height`.
  - Environment: the live scene's `scene.environment` is a PMREM cube-UV texture the tracer cannot sample. Build the tracer's own environment with the library's `GradientEquirectTexture` from the same colours `Lighting.tsx` uses (`ENV_GRADIENT`, `ENV_DUSK` warmed by altitude; read them there, duplicate the three constants into `pathtrace.ts` with a comment naming the source), and set `environmentIntensity` from `scene.environmentIntensity`. The sun is the scene's shadow-casting DirectionalLight, and the interior lamp pool (`src/three/FixtureLights.tsx`, point and spot lights, parked ones at intensity 0) traces as is at night; the tracer supports directional lights (confirm in the README; if it needs a `PhysicalSpotLight` or area light instead, build one at the sun's position with the same colour and intensity and say so).
  - Tracer settings: `bounces 5`, `transmissiveBounces 8`, `filterGlossyFactor 0.5`, `renderScale 1`, `tiles 2x2` (keeps the tab responsive), `multipleImportanceSampling true`, `textureSize` 1024 (procedural canvases are resampled into the texture array; check none is larger than that, otherwise raise it).
  - Progressive on-screen preview: set the renderer to `opts.width x opts.height` with `setSize(w, h, false)` and pixel ratio 1 (as `captureAt`), `renderToCanvas = true`, and call `renderSample()` from a `requestAnimationFrame` loop until `samples >= opts.samples` or `signal` aborts; report `onProgress(samples, total)` every frame. After the last sample copy the drawing buffer into a 2D canvas (as `renderToCanvas()` in capture.ts does) and encode a PNG. Restore size, pixel ratio, tone mapping, the camera and call `invalidate()` in `finally`; `dispose()` the tracer.
  - BVH build: use `setSceneAsync` (worker) if the README offers it; otherwise `setScene` is fine at this triangle count (under 100k).
- `src/lib/stills.ts` (+`.test.ts`, pure): `stillSize(viewerW, viewerH, maxSide = 1600)` (same aspect, longest side capped), `samplesFor(quality)` = high 256, balanced 128, low 48, `progressLabel(done, total, elapsedMs)` ("48 of 256 samples · about 40 s left" using a running average; "Building the scene…" before the first sample).
- Store (`src/store.ts`): one UI field `rendering: { id: string; done: number; total: number } | null`, not persisted, set through `setUi`. While set, `Viewer.tsx` forces `frameloop="never"` for the viewer with that `captureId` (one line next to the existing `frameloop` computation) so the on-demand loop never draws over the progressive image.
- UI (`src/components/ReportPanel.tsx`, next to the PNG snapshot buttons): a **Render** button per 3D view. It opens a small dialog (`.panel-dialog` pattern used elsewhere in components; look for an existing modal/`Dialog` helper and reuse it) with `<Loader kind="fill">` beside the progress label, a Cancel button (aborts the signal, keeps nothing), and on completion a preview `<img>` with **Save PNG** (uses `downloadBlob`, name `${prefix}-render-${label}-${date}.png`, stamped like snapshots when `stamp` is on) and **Close**. Also a palette entry in `src/lib/commands.ts` ("Render a still of the 3D view") when a 3D view is on screen. Phone chassis: same button; add one line under it, "Slow on a phone", nothing else.
- Saved views (`src/components/SavedViews.tsx`): a **Render** action per saved view that calls `renderStill` with that view's pose; same dialog. Call: skip if the dialog cannot be shared cleanly, and say so.

**Acceptance.**
- `stills.test.ts` covers size capping, sample counts and the label.
- `npm run check`, `npm run build`; in the build output the tracer lands in its own lazy chunk (name it `pathtrace` via the existing chunk grouping in `vite.config.ts` if a group list exists; otherwise just confirm it is not in `index`, `Viewer` or `capture` chunks).
- Headless check: SwiftShader exposes `EXT_color_buffer_float`, so the tracer runs. Render 4 samples at 320x240 of the home view via the store/UI; the resulting PNG is not black (mean luminance above 0.05) and the console shows no errors. Screenshot the dialog mid-render and the preview; put PNGs in the scratchpad `stills/` folder. Then a full 64-sample 800x533 render to look at: windows should show the room behind, the ground under the eaves should be darker than the open patio, and the sky side of the house lighter than the ground side.
- Live view after Cancel and after Save is unchanged: same size, orbit works, shadows redraw.

## 2. Lighting fidelity

**Why.** The live view lights with a hand-tuned gradient environment and a sun whose colour is a lerp; the sky dome drawn behind the house is a different, physical model. Making the environment come from the physical sky at the current sun position, and putting sun and sky on one scale, makes materials respond to time of day consistently and gives the path tracer the same answer as the orbit view.

**Files: `src/three/Lighting.tsx` only, plus a new pure `src/lib/skyModel.ts` (+`.test.ts`).**

- **Bake the physical sky, not a gradient, during a sun study.** The comment in `useSkyEnvironment` says the Sky draws nothing into PMREM's cube camera. The cause is scale: the cube camera there is `new THREE.CubeCamera(0.1, 100, cube)` and the backdrop Sky is scaled to 400, beyond its far plane. Build a second `Sky` (`makeSky(1)`, unscaled brightness) in a private scene, scaled to 50, aimed with `aimSky(sky, sunVector, altitude)`, and render it into the SAME `WebGLCubeRenderTarget` with the same `CubeCamera`, then keep `rt = pmrem.fromCubemap(cube.texture, rt)` exactly as now. Main's rule (see the comment above `useSkyEnvironment`): `scene.environment` must stay the same texture object across bakes, because a new one sends every lit material back through program selection and allocates 6 MB. The Sky writes depth, so the cube target may need `depthBuffer: true` back; measure nothing, just confirm the bake draws. Keep the gradient bake for the no-sun default and for night (`nightDark`, `NIGHT_ALTITUDE`, where the physical sky is black). Keep the 250 ms rebake throttle; rebake when the sun vector changes by more than 1° or the altitude crosses a 0.5° step, not on every frame of a playing study.
- **One scale.** The Sky's radiance is far above the gradient's, so set `scene.environmentIntensity` from a measured calibration: render the baked map's average radiance once (read back a 4x4 mip of the PMREM target, or sample the Sky shader at 16 directions on the CPU by porting its sky-colour function to `skyModel.ts`) and scale so that at 50° altitude the environment contributes the same ambient level the gradient does today (`ENV_INTENSITY = 0.8`). The sun's key light then takes its colour from the same model (`skyModel.sunColour(altitude)`: the Sky shader's sun transmittance by Rayleigh and Mie extinction, normalised to `WHITE_SUN` at 50°) and its intensity from `KEY_SUN * daylight(altitude).sun` as now. Delete `WHITE_SUN`/`LOW_SUN` lerp once the model replaces it. Put the maths in `skyModel.ts` with tests: colour at 50° is near white, at 2° is warmer (red/blue ratio above 1.4), monotonic warmth as altitude falls, zero sun below the horizon.
- **Hemisphere light.** With a real sky in the environment, halve the hemisphere light's intensity during a sun study (keep it as is outside one) so the ground bounce stays but the sky part is not counted twice. Call: remove it entirely in studies if screenshots look better.
- **Exposure.** Keep Neutral tone mapping and exposure 1 in the day. Between 6° and -4° altitude ease `gl.toneMappingExposure` from 1 to 1.25 so dusk does not go muddy; set it in the Lighting component's effect, restore on unmount, and `invalidate()`. This value is read by the still renderer too (it uses the same renderer), which is intended.
- **Do not change**: the shadow code (another agent just tuned it), `SkyBackdrop`, fog, glass behaviour, night handling (`nightDark`, `NIGHT_SKY`, `NIGHT_HEMI`), or the lamp light pool (`src/three/FixtureLights.tsx`, `src/lib/lights.ts`, `src/three/lampPool.ts`): the interior lamps are real point and spot lights already, precompiled in both states by `Precompile` in `frameLoop.tsx`; your environment texture must keep its identity so that precompile stays valid.

**Acceptance.**
- `skyModel.test.ts` as above; `npm run check`, `npm run build`.
- Screenshots (1440x900, rear view, June 21) at 09:00, 15:00, 19:30 and 21:30, before (git stash) and after, in the scratchpad `sky/` folder. After: the house's shaded faces take on sky blue at midday and warm orange at 19:30; the rendered wall under the eaves is not black; 21:30 matches before (night path unchanged). No-sun default view is pixel-identical or within noise to before.
- A playing sun study (store `sun` hour stepping 0.1 h every 100 ms for 3 s) causes at most 12 rebakes (count them with a console log you remove before committing) and no visible flicker.

## 3. Material depth from the canvases we already paint

**Why.** Every finish is a painted canvas with a bump map taken from a painted height canvas. Bump mapping is cheap but flat-looking: it has no mipmapped normals, so relief shimmers at distance and vanishes at grazing angles, and the path tracer ignores bump maps entirely while it supports normal, roughness and clearcoat. Deriving normal and roughness maps from the same canvases gives raking sun light real bite on brick, tiles, boards and slates, keeps the single-file hosted build free of downloads, and makes the stills match the live view.

**Files.** `src/three/textures.ts`, `src/three/wallTextures.ts`, `src/three/roofTextures.ts`, `src/three/Site.tsx` (neighbour roof material lines ~800-815 only), `src/three/Fixtures.tsx` (the `Finish` material factory around lines 165-185 only), `src/three/Roof.tsx` (the material lines ~185-195 only), new `src/three/normalMaps.ts`, new pure `src/lib/heightNormal.ts` (+`.test.ts`).

- **`heightNormal.ts` (pure, tested).** `heightToNormal(height: Uint8ClampedArray | Float32Array, w, h, strength, wrap = true): Uint8ClampedArray` (RGBA, tangent-space, +y up as three expects, Sobel 3x3, wrapping at the edges so tiles never seam). Tests: flat input gives (128,128,255); a ramp rising in +x gives red below 128 (three's convention: check `normalScale` sign by a tiny render if unsure, and document it); wrap: the gradient at column 0 uses column w-1; strength scales the tilt linearly.
- **`normalMaps.ts`.** `normalFromHeight(canvas, strength, tile): THREE.CanvasTexture` (reads the height canvas's pixels once, builds the normal canvas, `toTexture(..., false)` with repeat from `tile`), cached by the same key scheme as `heightMaps` in textures.ts, disposed in the same places (`dropOldFloorMaps`, `inUse`, `trackScene`). `roughnessFromPainted(painted, finish): THREE.CanvasTexture | null`: a greyscale canvas at half size where mortar/grout/joints (dark in the height canvas) are rougher and faces are the finish's base roughness; for wood, a faint grain modulation from the colour canvas's luminance. Three multiplies `roughnessMap` by `roughness`, so set `roughness: 1` on materials that get a map and bake the base level into the map.
- **Switch bump to normal everywhere it is painted**: `ext` walls (`WALL_TILE`, `drawWall` height), `cover` patterns (`drawCover` height, including the modern covers from wallTextures), floors (`drawFloor` height), roof tiles (`roofTextures.tileTextures` gains `normal`, keep `bump` in the type for one release only if something else reads it, otherwise drop it), neighbour roofs in Site.tsx. `normalScale` per finish, tuned so relief matches today's bump look at midday and reads clearly at raking light: start at brick 1.0, stone 1.2, cladding 0.8, pebbledash 0.6, tiles 0.8, slate 0.5, boards 0.5, roof tiles 1.0. Render stays flat (no map), as now.
- **Clearcoat.** In the Fixtures material factory, `gloss` becomes `MeshPhysicalMaterial` with `clearcoat 1`, `clearcoatRoughness 0.12`, base `roughness 0.35`; `satin` gets `clearcoat 0.4`, `clearcoatRoughness 0.4`. Add to `MatSpec` in textures.ts an optional `clearcoat?: number` on `plain` (include it in `matKey`), and use it for the front door, garage door and any gloss-painted leaf (find where `openings.ts` leaf colours become materials; `grep -n "plain" src/three/House.tsx src/three/shell.ts src/lib/openings.ts`). Sheen on fabrics: call, only if the fabric finish is already distinct in the factory; otherwise skip and say so.
- **Memory.** Normal maps are the height canvas's size; roughness maps half. Report `gl.info.memory.textures` before and after on the built-in house with the garden shown; the increase should be under 60 textures. Keep `generateMipmaps` on and anisotropy as the factories set it (another agent is raising it to 16; if that line conflicts on merge keep 16).

**Acceptance.**
- `heightNormal.test.ts` as above; `npm run check`, `npm run build`.
- Screenshots (1440x900) before and after at a raking sun (June 21, 18:30, rear view and front view) and at midday (15:00, home view), in the scratchpad `materials/` folder: brick courses, roof tiles and floorboards show directional relief at 18:30 that follows the light; no tile seams on walls or roofs; at midday the look is close to today's, not noisier. One phone-size (390x844) shot to confirm nothing breaks on the low setting.
- Zoom to 60 m away (store/orbit) and confirm the brick does not sparkle (mipmaps working).

## 4. Screen-space reflections and bounce light on the high setting, behind a toggle

**Why.** The orbit view's lighting is direct light plus a baked environment and N8AO. Screen-space reflections put the sky and the garden into the glass and gloss floors; screen-space global illumination adds bounced colour (lawn onto render, a red door onto the step). Both are finicky and cost GPU time, so they ship **off by default, behind two toggles on the high setting only**, so the owner can judge them in use before deciding.

**Library reality on three 0.185.** `realism-effects@1.1.2` (0beqz; `SSGIEffect` with reflections and GI in one, `TRAAEffect`, `VelocityDepthNormalPass`) is the only SSGI for the pmndrs composer, but it was last published in May 2023, before three removed `WebGLMultipleRenderTargets` (r172) and changed other renderer internals, so it may fail to import or render. Three's own `examples/jsm/postprocessing/SSRPass.js` is maintained and gives reflections only. Evaluate in this order and stop at the first that works:
1. Install `realism-effects` into the main checkout's node_modules (see section 1 for how; copy package.json and the lock into the worktree) and render one high-quality frame headless with `SSGIEffect` in the composer. If it throws, draws black, or needs patching three, drop it: do not patch node_modules or vendor the library. Say exactly what failed.
2. Otherwise wrap three's `SSRPass` in a pmndrs `Pass` adapter (`src/three/ssrPass.ts`: a class extending `Pass` from `postprocessing` that owns an `SSRPass`, forwards `setSize`, and in `render(renderer, input, output)` calls the SSRPass with the pmndrs buffers; SSRPass renders its own normal, metalness and depth passes with override materials, which ignore the section cut's clipping planes, so reflections of clipped geometry may appear; accept and note it). Reflections only; the GI toggle then reads "Bounce light: not available on this renderer" and is disabled.

**Toggles and UI.**
- `Settings` in `src/store.ts` gains `effects?: { reflections?: boolean; gi?: boolean }` (persisted with the rest of `settings`; absent means off, so no migration).
- `src/components/SettingsPanel.tsx`, under the Render quality switch: a row "Experimental, high quality only" with two checkboxes, **Reflections** and **Bounce light**, disabled (with a title saying why) unless quality is high. Brand tokens only; the row must read as experimental (a small "beta" pill is fine).
- A palette entry for each toggle in `src/lib/commands.ts` only if it is a one-liner.

**Rendering.**
- `src/three/Effects.tsx` stays the lazy chunk for N8AO and tone mapping. Put the experimental passes in a second lazy chunk, `src/three/ExperimentalEffects.tsx`, loaded only when a toggle is on (the pattern `Viewer.tsx` uses for `Effects`; extend the `before` hook so `Precompile` waits for it). Order in the composer: render, N8AO, SSR/SSGI, tone mapping, keeping `multisampling` as it is unless the pass cannot run under MSAA (then drop MSAA while a toggle is on and say so).
- Frames are on demand. Reflections from `SSRPass` are single-frame and work as is. SSGI with temporal accumulation needs successive frames to converge: while the GI toggle is on and the 3D tab is shown, keep `invalidate()` going for 24 frames after any change (a small hook that re-arms on store changes and camera moves via `OrbitControls`' change event), never a permanent `frameloop="always"`.
- Glass: the windows use physical transmission on high; if SSR on transmissive glass doubles up or sparkles, exclude the glass materials from the pass (SSRPass has a `selects` list) and say so.
- Compare mode mounts two viewers; both honour the toggles.

**Files you own.** `src/three/Effects.tsx`, new `src/three/ExperimentalEffects.tsx`, new `src/three/ssrPass.ts`, `src/components/SettingsPanel.tsx` (+ its css), `src/store.ts` (the `effects` field only), `src/lib/commands.ts` (two entries at most), and a minimal edit to `src/three/Viewer.tsx` (the lazy load and the `before` hook). `package.json`/`package-lock.json` only if realism-effects stays.

**Acceptance.**
- `npm run check`, `npm run build`; the experimental chunk is lazy and not in `index`, `Viewer` or `Effects`.
- Headless screenshots (balanced is not enough here: use high quality, 1000x650 viewport, long waits) of the rear view at 15:00 with: both off, reflections on, GI on if available; and the home view with the section cut at a ground-floor stop and reflections on. Reflections should show sky or garden in the patio doors and on the gloss kitchen units; nothing should flicker between two consecutive screenshots with no change. Toggling must not break the on-demand loop: with both off again, 3 s idle produces no frames (check `gl.info.render.frame` through a temporary dev hook you remove before committing).
